
**1. 세 가지 다른 명령어 니모닉(mnemonic)의 예를 제공하시오.**

* **답:** `MOV`, `ADD`, `SUB` (그 외에도 `JMP`, `CALL`, `INC` 등 다양한 명령어가 있습니다.)

**2. 호출 규약(calling convention)이란 무엇이며, 어셈블리어 선언에서 어떻게 사용되는가?**

* **답:** 호출 규약은 함수(프로시저)를 호출할 때 인자를 전달하는 방식, 스택을 정리하는 주체(호출자 또는 피호출자), 반환값을 처리하는 방법 등을 정의한 규칙입니다. 어셈블리 선언부에서는 어셈블러가 프로시저 호출 시 올바른 스택 프레임을 설정하고 인자를 관리할 수 있도록 지시하기 위해 사용됩니다 (예: `stdcall`, `cdecl`).

**3. 프로그램에서 스택(stack) 공간을 어떻게 예약하는가?**

* **답:** `.stack` 디렉티브(지시어)를 사용하여 스택 크기를 예약합니다. (예: `.stack 4096`)

**4. '어셈블러 언어(assembler language)'라는 용어가 왜 완전히 정확하지 않은지 설명하시오.**

* **답:** '어셈블러(Assembler)'는 프로그래머가 작성한 코드를 기계어로 번역해 주는 '번역기(프로그램)'를 뜻하며, 프로그래머가 작성하는 코드의 언어 자체는 '어셈블리(Assembly)'입니다. 따라서 '어셈블리 언어(Assembly Language)'라고 부르는 것이 정확합니다.

**5. 빅 엔디안(big endian)과 리틀 엔디안(little endian)의 차이점을 설명하시오. 또한 웹에서 이 용어의 기원을 찾아보시오.**

* **답:**
* **차이점:** **리틀 엔디안**은 데이터의 최하위 바이트(LSB)를 가장 낮은 메모리 주소에 저장하는 방식이고, **빅 엔디안**은 최상위 바이트(MSB)를 가장 낮은 메모리 주소에 저장하는 방식입니다.
* **기원:** 이 용어는 조나단 스위프트의 소설 *걸리버 여행기*에서 유래했습니다. 소설 속 소인국에서 삶은 달걀을 깰 때 넓은 쪽(Big End)을 먼저 깰 것인지, 좁은 쪽(Little End)을 먼저 깰 것인지를 두고 파벌이 나뉘어 전쟁을 벌이는 모습에서 컴퓨터 아키텍처의 바이트 저장 순서 논쟁을 빗대어 이름 붙여졌습니다.



**6. 코드에서 정수 리터럴(integer literal) 대신 심볼릭 상수(symbolic constant)를 사용하는 이유는 무엇인가?**

* **답:** 코드의 가독성을 높이고 유지보수를 쉽게 하기 위해서입니다. 상수 값을 변경해야 할 때, 코드 전체를 뒤져서 숫자를 수정할 필요 없이 상수가 정의된 한 곳만 수정하면 되기 때문입니다.

**7. 소스 파일(source file)과 리스팅 파일(listing file)은 어떻게 다른가?**

* **답:** **소스 파일**은 프로그래머가 텍스트 에디터로 작성한 원래의 어셈블리 코드가 들어있는 파일입니다. 반면 **리스팅 파일**은 어셈블러에 의해 생성되는 파일로, 소스 코드와 함께 번역된 기계어 코드, 메모리 오프셋 주소, 기호 테이블, 그리고 오류 메시지 등을 한눈에 볼 수 있도록 컴파일 결과를 정리해 놓은 파일입니다.

**8. 데이터 레이블(data label)과 코드 레이블(code label)은 어떻게 다른가?**

* **답:** **데이터 레이블**은 데이터 세그먼트에서 변수처럼 사용되며 특정 데이터가 저장된 메모리 위치를 나타냅니다 (보통 뒤에 콜론이 붙지 않습니다). **코드 레이블**은 코드 세그먼트 내에 위치하며 분기(JUMP)나 반복문, 프로시저 호출의 목적지 주소로 사용됩니다 (보통 콜론 `:`으로 끝납니다).

**9. (참/거짓): 식별자(identifier)는 숫자로 시작할 수 없다.**

* **답:** **참 (True).** 대부분의 프로그래밍 언어와 마찬가지로 어셈블리어에서도 식별자의 첫 글자로 숫자를 사용할 수 없습니다.

**10. (참/거짓): 16진수 리터럴은 0x3A와 같이 작성할 수 있다.**

* **답:** **거짓 (False).** (MASM 등 전통적인 어셈블러 교재 기준) 일반적인 어셈블리어에서는 16진수를 나타낼 때 `3Ah`와 같이 접미사 `h`나 `H`를 사용하여 표기합니다. `0x` 접두어는 C나 C++ 등의 언어에서 주로 사용하는 방식입니다.

**11. (참/거짓): 어셈블리 언어 디렉티브(directives)는 런타임(runtime)에 실행된다.**

* **답:** **거짓 (False).** 디렉티브(지시어)는 프로그램이 실행될 때(런타임) 작동하는 명령어가 아니라, 소스 코드를 기계어로 번역하는 '어셈블리 타임'에 어셈블러에게 특정한 동작을 지시하기 위해 사용됩니다.

**12. (참/거짓): 어셈블리 언어 디렉티브는 대문자와 소문자를 임의로 섞어서 작성할 수 있다.**

* **답:** **참 (True).** 기본적으로 MASM과 같은 어셈블러는 대소문자를 구분하지 않으므로 섞어서 작성해도 무방합니다.

**13. 어셈블리 언어 명령어(instruction)를 구성하는 네 가지 기본 요소를 말하시오.**

* **답:** 레이블(Label), 니모닉/명령어(Mnemonic), 피연산자(Operand), 주석(Comment).

**14. (참/거짓): MOV는 명령어 니모닉의 한 예이다.**

* **답:** **참 (True).**

**15. (참/거짓): 코드 레이블 뒤에는 콜론(:)이 오지만, 데이터 레이블은 콜론으로 끝나지 않는다.**

* **답:** **참 (True).**

**16. 블록 주석(block comment)의 예를 보여주시오.**

* **답:** MASM 기준 `COMMENT` 디렉티브와 사용자 지정 구분자(예: `!`)를 사용합니다.
```assembly
COMMENT !
이 부분은 블록 주석입니다.
여러 줄에 걸쳐 설명을 작성할 수 있습니다.
!

```



**17. 변수에 접근하는 명령어를 작성할 때 숫자(하드코딩된) 주소를 사용하는 것이 좋지 않은 이유는 무엇인가?**

* **답:** 프로그램이 수정되어 코드가 추가되거나 삭제되면 데이터가 메모리에 적재되는 실제 주소도 변하게 됩니다. 숫자 주소를 직접 코드에 적어두면 이러한 변화가 생길 때마다 모든 주소 값을 수동으로 다시 계산하고 수정해야 하여 오류가 발생하기 쉽습니다. 레이블(이름)을 사용하면 어셈블러가 이러한 주소 계산을 자동으로 처리해 줍니다.

**18. ExitProcess 프로시저에 전달되어야 하는 인수 유형은 무엇인가?**

* **답:** 32비트 정수(반환 코드)가 전달되어야 합니다. 일반적으로 프로그램이 성공적으로 종료되었음을 알리기 위해 `0`을 전달합니다.



**19. 프로시저(procedure)를 끝내는 디렉티브(directive)는 무엇인가?**

* **답:** `ENDP` 디렉티브를 사용합니다.



**20. 32비트 모드에서 END 디렉티브에 있는 식별자(identifier)의 목적은 무엇인가?**

* **답:** 프로그램의 실행이 시작되는 진입점(Entry point)을 지정합니다. 운영체제는 이 식별자가 가리키는 주소부터 명령어 실행을 시작합니다.



**21. PROTO 디렉티브의 목적은 무엇인가?**

* **답:** 외부 프로시저의 프로토타입을 선언하여 어셈블러가 해당 프로시저를 호출할 때 올바른 매개변수(인수)가 전달되는지 타입과 개수를 검사할 수 있도록 합니다.



**22. (참/거짓): 목적 파일(Object file)은 링커(Linker)에 의해 생성된다.**

* **답:** **거짓 (False)**. 목적 파일은 어셈블러(또는 컴파일러)에 의해 생성됩니다. 링커는 이 목적 파일들을 모아 실행 파일(Executable)을 만듭니다.



**23. (참/거짓): 리스팅 파일(Listing file)은 어셈블러에 의해 생성된다.**

* **답:** **참 (True)**.



**24. (참/거짓): 링크 라이브러리는 실행 파일을 생성하기 직전에 프로그램에 추가된다.**

* **답:** **참 (True)**. 링커가 목적 파일과 링크 라이브러리를 결합하여 최종 실행 파일을 만듭니다.



**25. 32비트 부호 있는(signed) 정수 변수를 생성하는 데이터 디렉티브는?**

* **답:** `SDWORD`

**27. 64비트 부호 없는(unsigned) 정수 변수를 생성하는 데이터 디렉티브는?**

**28. 8비트 부호 있는 정수 변수를 생성하는 데이터 디렉티브는?**

### **3.9.2 Algorithm Workbench**

**1. 10진수, 2진수, 8진수, 16진수 형식으로 정수 25를 나타내는 네 개의 심볼릭 상수를 정의하라.**

**2. 시행착오를 통해 프로그램이 여러 개의 코드와 데이터 세그먼트를 가질 수 있는지 알아보라.**

* **답:** 예, 가질 수 있습니다. 소스 코드 내에서 `.data`와 `.code` 디렉티브를 여러 번 번갈아 사용하여 세그먼트를 정의할 수 있으며, 어셈블러가 이를 알아서 결합해 줍니다.



**3. 빅 엔디안(big endian) 형식으로 메모리에 저장되는 더블워드(doubleword)에 대한 데이터 정의를 생성하라.**

* **답:** x86 시스템은 기본적으로 리틀 엔디안을 사용하므로, 빅 엔디안으로 32비트 데이터를 저장하려면 `BYTE` 디렉티브를 사용해 바이트 순서를 직접 지정해야 합니다 (예: 12345678h 저장 시).
```assembly
bigEndianVal BYTE 12h, 34h, 56h, 78h

```



**4. DWORD 타입의 변수를 선언하고 음수 값을 할당할 수 있는지 확인하라. 이것이 어셈블러의 타입 검사에 대해 무엇을 말해주는가?**

* **답:** `myVal DWORD -1`과 같이 할당이 가능합니다. 이는 어셈블러가 `DWORD`(부호 없음)와 `SDWORD`(부호 있음)를 엄격하게 구분하여 에러를 내기보다는, 단지 32비트 크기의 메모리 공간을 할당할 뿐이며 해당 데이터의 해석은 전적으로 프로그래머에게 맡긴다는 것(약한 타입 검사)을 의미합니다.



**5. EAX에 5를 더하고, EDX에 5를 더하는 두 명령어를 작성하라. 리스팅 파일을 생성하고 기계어 코드의 차이점을 확인하라.**

* **답:**
```assembly
add eax, 5
add edx, 5

```


이 두 명령어를 어셈블하여 기계어를 비교해보면, 연산(ADD)과 즉시값(5)에 대한 바이트는 유사하지만, 목적지 레지스터가 EAX인지 EDX인지 지정하는 레지스터 필드 비트 값이 다르게 인코딩된 것을 확인할 수 있습니다.



**6. 숫자 456789ABh가 주어졌을 때 리틀 엔디안 순서로 바이트 값을 나열하라.**

* **답:** `ABh, 89h, 67h, 45h`
