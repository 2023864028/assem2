### 1번 문제 풀이

초기값 `al = 0D4h`는 이진수로 `1101 0100b`입니다.

* **a. `shr al, 1` (논리적 우측 시프트)**
모든 비트가 우측으로 1칸 이동하며 빈자리(최상위 비트)는 `0`으로 채워집니다.
`1101 0100` ➔ `0110 1010`
**정답: `6Ah**`
* **b. `sar al, 1` (산술적 우측 시프트 1회)**
모든 비트가 우측으로 1칸 이동하며, 부호 유지를 위해 기존 최상위 비트(1)가 그대로 복사되어 채워집니다.
`1101 0100` ➔ `1110 1010`
**정답: `EAh**`
* **c. `sar al, 4` (산술적 우측 시프트 4회)**
부호 비트인 `1`을 유지하며 우측으로 4칸 이동합니다.
`1101 0100` ➔ `1111 1101`
**정답: `FDh**`
* **d. `rol al, 1` (좌측 순환 이동 1회)**
모든 비트가 좌측으로 1칸 이동하며, 최상위 비트(1)가 떨어져 나가 최하위 비트 자리로 이동합니다.
`1101 0100` ➔ `1010 1001`
**정답: `A9h**`

### 2번 문제 풀이

마찬가지로 초기값 `al = 0D4h` (`1101 0100b`)를 기준으로 수행합니다.

* **a. `ror al, 3` (우측 순환 이동 3회)**
우측으로 밀려난 3개의 비트 `100`이 최상위 비트 쪽으로 돌아갑니다.
`1101 0100` ➔ `1001 1010`
**정답: `9Ah**`
* **b. `rol al, 7` (좌측 순환 이동 7회)**
8비트 크기에서 좌측으로 7번 회전하는 것은 우측으로 1번 회전(`ror al, 1`)하는 것과 같습니다.
`1101 0100` ➔ `0110 1010`
**정답: `6Ah**`
* **c. `rcl al, 1` (캐리 포함 좌측 순환 이동 1회)**
앞선 `stc` 명령어로 캐리 플래그(CF)가 1이 됩니다. 좌측 이동 시 기존 CF(1)가 최하위 비트로 들어가고 최상위 비트는 새로운 CF가 됩니다.
`1101 0100` (CF=1) ➔ `1010 1001`
**정답: `A9h**`


* **d. `rcr al, 3` (캐리 포함 우측 순환 이동 3회)**
`stc` 명령어로 CF가 1이 된 상태에서 시작합니다. CF를 포함한 9비트가 회전합니다.
초기 상태: CF=`1`, AL=`1101 0100`
1회 이동: CF=`0`, AL=`1110 1010` (기존 CF인 1이 MSB로 삽입됨)
2회 이동: CF=`0`, AL=`0111 0101`
3회 이동: CF=`1`, AL=`0011 1010`
**정답: `3Ah**`

### 5번 문제 풀이

32비트 나눗셈 명령어입니다. `EDX:EAX(00000000_00123400h)`를 `EBX(10h)`로 나눕니다.

* 16진수에서 `10h`로 나누는 것은 자릿수를 우측으로 한 칸 밀어내는 것과 같습니다.
* 몫: `12340h` (이 값은 EAX에 저장됩니다)
* 나머지: `0` (이 값은 EDX에 저장됩니다)
* **정답: `EAX = 00012340h`, `EDX = 00000000h**`

### 6번 문제 풀이



이 코드는 16비트 나눗셈(`div bx`)을 수행합니다. 피제수(Dividend)는 `DX:AX` 레지스터 쌍으로 결합되며 `05004000h`가 됩니다. 제수(Divisor)는 `BX` 레지스터의 값인 `10h`입니다.

* `05004000h / 10h = 00500400h`입니다.
* 16비트 나눗셈의 몫은 16비트 레지스터인 `AX`에 저장되어야 하지만, 계산된 몫 `500400h`는 `AX`의 최대 수용 크기인 `FFFFh`를 초과합니다.

따라서 레지스터에 몫이 정상적으로 저장되지 않고 **나눗셈 오버플로우(Divide Overflow) 예외가 발생**합니다.

### 7번 문제 풀이



캐리 플래그(Carry Flag)를 포함하여 덧셈을 수행하는 `adc` 명령어입니다.

* `mov bx, 5`: `BX`에 `5`를 저장합니다.


* `stc`: 캐리 플래그(CF)를 `1`로 설정합니다.


* `mov ax, 60h`: `AX`에 `60h`를 저장합니다.


* `adc bx, ax`: `BX = BX + AX + CF` 연산을 수행합니다.


* 즉, `5 + 60h + 1 = 66h`가 됩니다.

정답은 `BX = 0066h`입니다.

### 8번 문제 풀이



64비트 모드의 나눗셈입니다. `RDX:RAX` 쌍이 피제수, `divisor`가 제수가 됩니다.

* `RDX`(dividend_hi) = `0000000000000108h`
* `RAX`(dividend_lo) = `0000000033300020h`
* 피제수 `RDX:RAX` = `0000010833300020h` (결합된 값)
* 제수 `divisor` = `100h`

16진수에서 `100h`로 나누는 것은 값을 오른쪽으로 2자리(8비트) 이동시키는 것과 동일합니다. 따라서 몫은 `0000000108333000h`가 되고 나머지는 `20h`가 남습니다.

결과적으로 몫이 저장되는 **`RAX = 0000000108333000h`**, 나머지가 저장되는 `RDX = 0000000000000020h`가 됩니다.

### 9번 문제 풀이



`val1`에서 `val2`를 빼는 루프 과정에서 두 가지 주요 논리적 오류가 있습니다.

1. **메모리 주소 지정 오류**: `esi`와 `edi` 레지스터에 배열의 첫 번째 값이 아니라 메모리 주소(포인터)를 전달해야 합니다. 현재는 `OFFSET` 연산자가 누락되어 있습니다.


* **수정**: `mov esi, OFFSET val1` 및 `mov edi, OFFSET val2`


2. **포인터 증감 오류**: x86 리틀 엔디안(Little-Endian) 아키텍처에서는 다중 바이트 값의 가장 낮은 자리 바이트가 가장 낮은 메모리 주소에 위치합니다. 하위 바이트부터 뺄셈(`sbb`)을 수행하고 상위 바이트로 넘어가려면 주소 포인터를 감소(`dec`)시키는 것이 아니라 증가(`inc`)시켜야 합니다.


* **수정**: `dec esi`를 `inc esi`로, `dec edi`를 `inc edi`로 변경합니다.

### 2. Extended Subtraction Procedure



임의의 크기를 가진 두 이진 정수를 빼는 `Extended_Sub` 프로시저를 만드는 문제입니다.

* **조건:** 두 정수의 저장 크기는 같아야 하며 32비트의 배수여야 합니다. 테스트 프로그램은 10바이트 이상의 정수 쌍을 전달해야 합니다.


* **해결 방향:** 큰 수의 뺄셈이므로 캐리 플래그를 처리해야 합니다. 첫 번째 뺄셈은 `sub`로, 이후의 뺄셈은 빌림(borrow)을 고려하는 `sbb` 명령어를 사용하여 하위 비트부터 상위 비트 방향으로 루프를 돌며 계산합니다.

### 3. Packed Decimal Conversion



4바이트 팩 10진수(Packed Decimal) 정수를 ASCII 10진수 문자열로 변환하는 `PackedToAsc` 프로시저를 작성하는 문제입니다.

* **입력:** 팩 정수, ASCII 문자를 저장할 버퍼 주소


* **해결 방향:** 팩 10진수는 한 바이트에 2개의 10진수 숫자(니블 단위)가 들어있습니다. 바이트 단위로 읽어와 상위 니블과 하위 니블을 분리한 후, 각각 `30h`를 더해 ASCII 문자로 변환하여 버퍼에 저장합니다.

### 4. Encryption Using Rotate Operations



회전(Rotate) 연산을 사용하여 평문을 암호화하는 프로시저를 작성하는 문제입니다.

* **암호화 키:** `key BYTE -2, 4, 1, 0, -3, 5, 2, -4, -4, 6`


* **동작:** 음수는 왼쪽으로 회전(rol), 양수는 오른쪽으로 회전(ror)을 의미하며, 숫자는 회전하는 크기를 나타냅니다. 평문의 각 바이트를 키 배열의 값에 따라 회전시킵니다. 키 배열(10바이트)이 끝나면 평문의 다음 10바이트에 키를 다시 정렬하여 반복합니다.


* **해결 방향:** 평문과 키 배열을 동시에 순회하는 루프를 만듭니다. 키 값을 읽어 양수/음수를 판별하고 분기하여 해당 바이트를 `rol` 또는 `ror`로 회전시킵니다.

### 5. Prime Numbers



'에라토스테네스의 체(Sieve of Eratosthenes)' 알고리즘을 사용하여 2부터 1000 사이의 모든 소수를 찾아 출력하는 프로그램을 작성하는 문제입니다.

* **해결 방향:** 1000개의 바이트 배열을 생성하고 1(소수 후보)로 초기화합니다. 2부터 시작하여 현재 숫자가 1이면 소수로 간주하고, 그 숫자의 배수들에 해당하는 인덱스의 값을 0(합성수)으로 바꿉니다. 루프가 끝난 후 값이 1인 인덱스만 출력합니다.

제시된 이미지는 어셈블리 언어 프로그래밍 과제 3개(6번, 7번, 8번)를 포함하고 있습니다. 각 문제의 내용과 어셈블리 구현을 위한 핵심 로직을 한국어로 요약해 드립니다.

### 6. 최대공약수 (Greatest Common Divisor, GCD)



두 정수의 최대공약수를 구하는 유클리드 호제법 알고리즘을 어셈블리로 구현하는 문제입니다. 제시된 C++ 의사 코드(pseudocode)를 바탕으로 작성합니다.

* **요구사항:** GCD 함수를 작성하고, 여러 다른 값들을 넘겨 테스트하는 프로그램을 작성하여 화면에 결과를 출력해야 합니다.


* **구현 포인트:**
1. 전달된 두 인수 `x`, `y`의 절댓값을 구합니다 (`cmp`와 `neg` 명령어 활용).


2. `do-while` 루프 내에서 나눗셈(`div` 또는 `idiv`)을 수행하여 나머지(`n = x % y`)를 구합니다. 이때 나머지는 `EDX` 레지스터에 저장됩니다.


3. `x`에 `y`값을 넣고, `y`에 나머지 `n`을 넣는 과정을 `y`가 0보다 클 때까지 반복합니다.


4. 루프가 종료되면 `x` 값이 최대공약수가 되며 이를 반환합니다.





### 7. 비트 단위 곱셈 (Bitwise Multiplication)



곱셈 명령어(`mul`, `imul`)를 사용하지 않고, **시프트(Shift)와 덧셈(Add)** 연산만을 사용하여 32비트 부호 없는 정수를 곱하는 `BitwiseMultiply` 프로시저를 작성하는 문제입니다.

* **입출력:** 곱할 값(Multiplier)은 `EBX`로 전달받고, `EAX`에 있는 값(Multiplicand)과 곱하여 결과를 `EAX`로 반환합니다 (오버플로우는 없다고 가정).


* **구현 포인트:**
1. 결과를 누적할 레지스터(예: `EDX`)를 0으로 초기화합니다.
2. 승수(`EBX`)를 우측으로 시프트(`shr`)하면서 떨어져 나가는 비트(캐리 플래그, CF)를 검사합니다.


3. 만약 캐리가 1이라면(즉, 현재 비트가 1이라면), 현재의 피승수(`EAX`) 값을 누적 레지스터(`EDX`)에 더합니다.
4. 피승수(`EAX`)는 다음 자리 계산을 위해 좌측으로 1비트 시프트(`shl`)합니다.
5. 승수(`EBX`)가 0이 될 때까지 이 과정을 반복하고, 최종 누적값을 `EAX`로 옮겨 반환합니다.



### 8. 팩 10진수 덧셈 (Add Packed Integers)



7.6.1절의 `AddPacked` 프로시저를 확장하여, **임의의 길이(크기)를 가진 두 팩 10진수(Packed Decimal) 배열을 더하는** 문제입니다.

* **요구사항:** 두 배열의 길이는 같아야 하며, 4바이트, 8바이트, 16바이트 크기의 정수 쌍을 테스트해야 합니다.


* **레지스터 사용 권장안:**
* `ESI` : 첫 번째 숫자 배열의 포인터


* `EDI` : 두 번째 숫자 배열의 포인터


* `EDX` : 덧셈 결과를 저장할 배열의 포인터


* `ECX` : 더할 바이트 수 (루프 카운터)




* **구현 포인트:**
1. 팩 10진수는 `BCD`(Binary Coded Decimal) 연산이 필요하므로, 각 바이트를 더할 때 캐리를 포함하는 덧셈(`adc`)을 수행한 직후 반드시 `daa` (Decimal Adjust AL after Addition) 명령어를 사용하여 10진수 보정을 해주어야 합니다.
2. 하위 바이트(낮은 주소)부터 상위 바이트로 이동하며 루프(`loop`)를 돕니다. 포인터(`ESI`, `EDI`, `EDX`)는 각각 1씩 증가(`inc`)시켜야 합니다.
